5 правил хорошої роботи з Git
1.	Робіть невеликі й логічні коміти. Записуйте зміни часто, але розділяйте різні завдання на окремі коміти. Один коміт повинен вирішувати одну невелику задачу. 
2.	Пишіть зрозумілі повідомлення. Формулюйте назви комітів чітко: коротко описуйте суть змін у наказовому способі (наприклад, «додано валідацію форми» замість «виправлено купу всього»). 
3.	Давайте гілкам значущі назви. Називайте гілки інформативно, використовуючи префікси на кшталт feature/, bugfix/ або hotfix/, щоб одразу було зрозуміло призначення робіт. 
4.	Часто робіть git pull. Оновлюйте свій локальний репозиторій з віддаленого якомога частіше, особливо перед тим як відправляти свої зміни (git push). Це дозволяє виявити конфлікти на ранніх етапах. 
5.	Не поспішайте робити git push. Перевірте свої зміни за допомогою git status та git diff перед відправкою на сервер. Переконайтеся, що ви не надсилаєте випадкові файли, логи чи зайвий тестовий код.
